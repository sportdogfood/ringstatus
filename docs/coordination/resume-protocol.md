# Resume and checkpoint protocol

Operating procedure for this coordinating work, implemented as documents on 8 October 2026 following the owner's request. No hook, timer, resident agent, automatic alert or periodic automation was installed.

## Review triggers

Maintain these blocks after an important decision, target/scope change, runner start/stop, confirmed failure or verified completion. Keep one rs-decisions row per important decision. Record supersession rather than silently erasing history.

Review context every20substantive exchanges or60minutes of active coordinating work, whichever comes first. Treat this as a manual housekeeping interval, not a known model reliability threshold. At a major phase change, repeated context correction or before changing runner ownership, refresh the blocks and prepare a handoff. Do not auto-create chats without owner authorization. Automatic compaction is not durable project documentation.

## Receiving chat: required first steps

1. Read README and all five blocks. Verify the approved checkout and locally referenced evidence exist. Read relevant live rs-bases/rs-decisions rows through the Airtable connector; do not open a login page merely to read data. Missing access is a specific blocker, not permission to guess.
2. Read the current priority in README and obtain one compact status snapshot of that assigned runner. As of the 8 October owner update, this is the NEW Schedule draft runner; both previous Webflow runners remain stopped. Do not claim its browser tab or create a duplicate. The original no-new-project instruction applied to the transfer itself; a later explicit owner assignment supersedes that hold within its stated scope.
3. Reconcile stale facts with newer evidence: Barn checkpoint's initial BLOCKED/page_id=null is superseded by verified page creation and later native authoring. The direct resource-client auth failure did not invalidate the working Webflow app connector. Current Barn completion still requires fresh evidence; do not infer it.
4. Confirm in a compact receipt: files read, source/target IDs, current priority, active/stopped runners, missing sources, carried limits and next permitted action. Update README transfer receipt only after these checks. Delivery alone does not prove handoff acceptance.
5. Continue coordination within the latest owner authorization. Inspect the assigned runner through bounded status tools when needed, preserving build ownership. For an idle unfinished runner, inspect its reason before messaging: never override an owner stop, exhausted budget or real blocker; continue executable authorized work without an acknowledgment-only stall. No recurring monitor, new business process, schema task, publishing or unrelated code repair is implied. A running status is not evidence of useful progress or completion.

## Communication and boundaries

Short factual action/result messages. No repeated permission for already-approved steps, no acknowledgment-only stall, no invented completion, no unsolicited next phase. Ask only for a real missing decision/access requirement and explain its source. Preserve native visuals and functional work as separate deliverables without losing either backlog.

Codex is not the business runner. For a production cadence/workflow failure, stop; no alternate/manual endpoint as proof, no record repair, no patch after failed verification without separate APPROVED TO EDIT. Do not misapply that production rule as an extra approval gate for an already-authorized isolated prototype.

Only production Webflow tools, guide first; correct documented action/schema, no speculative API names. No proactive OAuth, reinstall, beta connection or publishing. Stop and report actual authentication errors from the tool being used. Keep unrelated working code/shared definitions immutable.

## Handoff packaging

Update existing blocks rather than append a second competing full summary. Canonical detailed state stays with each runner and Airtable registers; these blocks route to it and summarize current controlling decisions. Use a self-contained new-chat prompt with the index path and key boundaries. Verify the receiver actually read and reconciled the blocks before calling the transfer complete. Do not archive or delete the source chat automatically.
