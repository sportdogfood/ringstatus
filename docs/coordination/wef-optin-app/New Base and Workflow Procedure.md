# New Base and Workflow Procedure

Use this when the owner assigns a new Airtable base, a new workflow, or setup for a receiving agent. Keep one current task record. Use the existing source files and records for decisions, evidence and the next action.

## Set up the base and workflow

1. **Confirm the assignment.** Record the outcome, acceptance, approved workspace and target, coordinator, execution owner, and exact permission to create or change each part. Check the Agents registry and existing base before creating anything. Recover the working baseline, related consumers, current stops and protected data.
2. **Set up the minimum structure.** Reuse the existing base if it owns the work. Use the eight operating tables in the base guide: `system`, `tasks`, `agents`, `fails`, `activity`, `development`, `workflow` and `changes`. Reuse matching tables and links. Add only the agreed business tables and fields. Keep established IDs and ownership of shared data. Use the guide for exact fields, links and status choices. [Airtable base guide](</C:/Users/gombc/OneDrive - Sport Dog Food/github/repos/ringstatus/docs/coordination/new-airtable-base-guide.md>)
3. **Make the starting point usable.** Write the system record with START HERE, current health, sources, connections, owners, known gaps and one executable next task. Add the existing guide record where needed. Verify the base ID and access. Link the base and its real system checkpoint through the existing Agents `bases` registry and `Resume here`. Reconcile `base-lanes` and link the activity note. [Agents base register](https://airtable.com/appZahVgD156cMAe3/tbltaHwEyBfcuOHIm)
4. **Write the actual workflow.** For each ordered step record the trigger, time zone and cadence where applicable, owner, input source and stable keys, expected behavior, actual implementation, output and consumer. Document the approved primary path, what makes a result usable, when fallback is allowed, stop and escalation rules, and required evidence. Keep proposals in `development` and approved executable work in `tasks`. Separate receipt, processing, saved result and downstream completion.
5. **Prepare the agent README and instructions.** Use the authorized README location and identify where operational records are written. Reuse the existing README table or, when approved, create the per-agent table using the live template. Copy its heading order, headings, purpose and tags. Add the long-text content and verify it in the right order. Link the shared rules from **Development → Project global instructions**. Include only the skills and source paths that apply to this assignment. [Agents README template](https://airtable.com/appZahVgD156cMAe3/tblV2xNTpeEahfu13)
6. **Read back and hand off.** Verify base identity, fields, links, start record, workflow, current open tasks and instructions from the saved targets. Match the smallest authorized check to each acceptance item. Record schema and documentation readiness, primary and fallback results, scheduled execution, and downstream readback separately. Mark missing evidence **Unverified**. The designated runner executes live workflows. Use the existing route and preserve stops. Record the result and exact next action in the owning task and system checkpoint. ## README contract

| Order | Heading | What belongs there |
| --- | --- | --- |
| 1 | Current status | Release and state, next action, blockers and active stops. List only assigned or approved open tasks with status, date last confirmed open, and evidence. |
| 2 | Purpose and ownership | Scope, coordinator, active chat ID, aliases, related owners and boundaries. Put deprecated chats in history. |
| 3 | Inputs and outputs | Authoritative sources, keys, owned and shared outputs, consumers, connections and their owners. |
| 4 | How it works | Resume steps and applicable Collection cadence and fallback contract, Cleanup contract and Linker contract. Give alerts and escalation where relevant. Link each shared rule to its owner's source. |
| 5 | Handoffs | Trigger, sender, recipient, execution owner and evidence. Track delivery, acknowledgment and verified completion separately. |
| 6 | Future | Proposals and pending checks with the evidence or owner decision needed. |
| 7 | Development | Global and project instructions, urgent instructions, brief, applicable skills, code locations and review evidence. |

Use the current README contract for WEF roles and the verified coordinator for other domains. ## Instruction packet

Use the active instruction chain and the latest relevant owner decisions. Keep replies short and factual. Reuse the proven approach, finish authorized work, and stop the affected path at an unresolved blocker. Record which sources the receiver actually read. When a receiver cannot open a local path, include the essential current instruction text in the authorized handoff. Save an approved local copy or reference in the agent's existing source document, reopen it, and record the location and heading.
