## Triggers and request handling

- Legacy Detail subscribes to Pusher channel equal to class ID and event updateavailable. Handler calls GetData and SendDataToParent. A conditional 20-second timer refreshes where its data logic sets vb_timeoutSet. No listener installed by this investigation.
- Signup page subscribes to concatenated show ID + company ID + cgid and rowupdate. Handler JSON-parses the event and updates its grid. Event payload not captured; not claimed sufficient as an authoritative ingestion stream.
- Legacy frame sends {event:'getliveclass',data:live_class_obj} to its parent and accepts sendliveclass messages. This is derived browser data, not a separate HTTP endpoint.
- Main app configures Axios withCredentials=true and shared SGL-REQUEST-ORIGIN/cache headers; request interceptor reads stored access_token and sets bearer. Browser address-bar requests do not reproduce this Axios request.
- Main app reads /utilities/get-config with fetch credentials:'omit'. A response helper Qe extracts a sufficiently long _t into access_token and deletes _t from the response. Response interceptor then decodes protected objects recursively and retries a GET once when a new _t was extracted (__anonRetried). It deletes old authorization before calling Axios again; request interceptor can attach the newly stored token. This is source behavior, not newly installed proxy behavior.
- /iphone.php/esp/webservice/AuthenticateUserViaJWT bridges the app bearer to legacy session using token, datetimestamp, hash and from_wp_api. Found in source only; not invoked.
