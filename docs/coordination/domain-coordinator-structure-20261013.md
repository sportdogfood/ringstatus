## How each coordinator carries work to completion

1. Read current AGENTS.md, this map, the domain checkpoint and relevant shared contract. Establish exact authorized outcome, current source, proven baseline, protected boundaries, deadline and acceptance before dependent work.
2. Assign only needed disjoint tasks within available concurrency. A coordinator may manage two or three workers when authorized and useful; it need not create a worker per capability. Use one writer with independent read-only testing/review where appropriate.
3. Every dispatch includes exact scope, source/version, allowed targets, dependencies, skill paths, connector IDs, acceptance, time/cost limits, report destination and concrete first action. Never silently choose a different model/effort; record actual settings and unavailable telemetry honestly.
4. Check actual dispatch/progress and changed evidence. Do not nudge running workers or treat a saved handoff as dispatched. Continue independent authorized work while a dependency is blocked; carry the next executable transition after each worker result.
5. Keep source review, rendered UI review and live workflow proof separate. Use established human handoffs when needed, specifying who/action/location/evidence/resume condition. Codex does not substitute direct commands for the production runner.
6. Follow context-check-procedure.md at boundaries and the first tool boundary after 30 active minutes. Scheduled reminders require explicit scope, owner, expiry and quiet deduplication; they are best-effort supervision, not guaranteed enforcement. No schedule or stopped worker is restarted by this document.
7. Save actual outcome and next action in the domain base; maintain cross-base ownership/interfaces in Agents. A handoff preserves authorization, failures, exact versions, worker state and reminder ownership. Readback is required before claiming record updates complete.
