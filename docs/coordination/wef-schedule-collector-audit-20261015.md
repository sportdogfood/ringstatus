### What the trace actually proves
The saved report documents recurring normal scheduled acquisition failures: 180-second timeout with future rows persisted, and zero-row protection failures on a day the owner confirmed had no classes. Dependent calculation/trips/publication gates can block while independent live lanes still run. It does not time each internal operation. It does not show that the second table read alone caused the timeout.
A01/A02/A03 behavior has concrete source support; A04/A05/A06/A07 identify unnecessary or overbroad work. A08 separates dead-code weight from real execution cost. A09 lacks historical rationale. A11 is a statically proven error-reporting path, not an observed failed-write incident.

### History limits and correction to earlier planning
Commit authorship is the shared sportdogfood identity and many messages are “3”, “5”, “7”, “ch”, “11”, “234”. This cannot establish whether an agent, owner or another contributor made a choice or whether approval existed. Report “rationale not established,” not “agent drift proven.”
The earlier plan's blanket preserve archive/inactive/dropped_at recommendation is NOT a drop-in preservation of existing downstream behavior: source and tests explicitly require reactivation. This audit supersedes that assumption. The smallest safe design must retain legitimate source reactivation while respecting actual manual suppression rules. Do not silently expand manual_time_override to unrelated fields or create dozens of override flags.
Current manual_time_override protects only estimated_start_time. Other source fields are currently treated as source-owned. There is no generalized record-of-manual-edits mechanism; do not claim one exists.

### Proposed cleanup order (no implementation authorization)
1. Preserve endpoint/normalizer/key/fallback behavior and established downstream requirements.
2. Resolve lifecycle/manual-suppression distinction from actual current controls; retain known start-time override on both dates.
3. Correct required-write success propagation before any reliance on a new completion signal.
4. Extract per-day acquisition and move existing control maintenance deliberately, not by omission.
5. Narrow reads, eliminate unchanged source writes and timestamp-only scope churn where safe; keep two independent dates.
6. Remove proven unused remnants only after reference checks; retain justified compatibility/protections.
7. Verify on normal scheduled cadence after approval, including restart, unchanged repeat, valid empty day, failure and rollover. Record actual requests/durations; no invented performance target.

No code changed, no tests or business jobs run, no operational state repaired. Audit findings are development proposals, not E2E acceptance.
